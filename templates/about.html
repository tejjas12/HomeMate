Project Overview

Understanding the problem, objectives and expected output.

Problem Statement

Property prices vary according to location, property size, number of bedrooms, property category, furnishing and availability status. Manually estimating a reasonable price from several features can be difficult.

HomeMate uses historical property listings to learn relationships between property features and listed prices, then uses a trained regression model to estimate a price for a property described by the user.

Project Objectives

Understand property data

Inspect the dataset, its columns and value distributions.

2

Clean and transform data for machine learning.

3
Train and compare models

Evaluate Linear Regression and Decision Tree Regression.

4
Build an interactive application

Connect the trained model to a Flask website.

03

Data Cleaning

Preparing the raw listings before model training.

Raw property data can contain missing values, inconsistent formats, irrelevant records or values that cannot be used reliably for prediction. Data cleaning helps reduce these problems before the machine learning algorithms are trained.

1
Inspect missing values

Identify which columns contain missing values and determine whether those values need to be removed or imputed. This avoids silently treating missing information as valid data.

2
Check data types

Confirm that numerical fields such as price, size and BHK can be interpreted numerically, while fields such as city and property type remain categorical.

3
Validate price and size values

Check for invalid or unusable numerical values. A non-positive price, for example, is generally not meaningful as a property listing target.

4
Focus on residential records

Prepare the residential listing dataset used by HomeMate so that the model is aligned with the intended house price prediction task.

5
Review duplicates and consistency

Duplicate and inconsistent records should be inspected because repeated or conflicting records can distort the distribution of prices.

Why cleaning matters: Poor-quality data can teach a model incorrect relationships. Cleaning improves consistency, makes analysis more meaningful and helps prevent invalid inputs from affecting model evaluation.

Documentation note: These are the data-quality checks relevant to the workflow. Only checks actually present in the executed Colab notebook should be described in a formal report as completed operations; not every example above necessarily represents a separate executed command.

Exploratory Data Analysis (EDA)

Understanding patterns before building the model.

What is EDA?

Exploratory Data Analysis is the process of examining a dataset using summary statistics, tables and charts before fitting a machine learning model.

It helps identify distributions, unusual values, relationships between features and possible data-quality issues that require further investigation.

Analysis Relevant to HomeMate

A
Price distribution

Understand how listed property prices vary.

B
Size and BHK

Inspect property area and bedroom-count patterns.

C
City comparisons

Explore differences in listing prices across cities.

D
Category distribution

Inspect property types and categorical fields.

Why EDA was important

Property price data can have a wide numerical range. EDA helps identify whether a small number of expensive listings dominate the distribution, whether some categories are uncommon, and whether the selected features are useful for describing property listings.

The dashboard later presents city-wise prices and property type distributions as interactive charts, making these patterns easier to explore.

05

Feature Selection and Preprocessing

Converting the cleaned data into model-ready inputs.

Separating X and y

The model requires a set of input features and a target value. We define X as the seven property attributes and y as the property price to be predicted.

feature_columns = [ "Size", "No_of_BHK", "Property_type", "Property_status", "City_name", "is_furnished", "is_ready_to_move" ] X = df[feature_columns] y = df["Price"]
Why separate them?
This clearly identifies what the model is allowed to use as input and which value it must learn to predict.

Numerical and categorical preprocessing

Operation Purpose HomeMate relevance
Numerical imputation Handle missing numerical values. Helps the model receive usable numerical inputs.
Categorical imputation Handle missing categories where needed. Maintains usable city and property category values.
One-hot encoding Represent categories using numerical indicator columns. Allows models to use city and property type information.
Pipeline Keep preprocessing and model operations together. Ensures prediction inputs receive the same transformations.
# Illustrative preprocessing structure from sklearn.compose import ColumnTransformer from sklearn.pipeline import Pipeline from sklearn.impute import SimpleImputer from sklearn.preprocessing import OneHotEncoder numeric_features = ["Size", "No_of_BHK"] categorical_features = [ "Property_type", "Property_status", "City_name", "is_furnished", "is_ready_to_move" ] numeric_transformer = Pipeline(steps=[ ("imputer", SimpleImputer(strategy="median")) ]) categorical_transformer = Pipeline(steps=[ ("imputer", SimpleImputer(strategy="most_frequent")), ("encoder", OneHotEncoder(handle_unknown="ignore")) ]) preprocessor = ColumnTransformer(transformers=[ ("num", numeric_transformer, numeric_features), ("cat", categorical_transformer, categorical_features) ])

The code above illustrates a common preprocessing design. Use the exact executed notebook code when reproducing the implementation in a technical report.

06

Train-Test Split and Model Building

Training on one subset and evaluating on unseen records.

Train-Test Split: 80/20

The prepared data was split into a training set and a test set using an 80/20 split with random_state=42. The training set is used to fit the model; the test set is reserved for evaluating how well it predicts records that were not used during training.

Training Set
80%
Used to learn patterns from the data.
Test Set
20%
Used for model evaluation.
from sklearn.model_selection import train_test_split X_train, X_test, y_train, y_test = train_test_split( X, y, test_size=0.20, random_state=42 )
Why random_state=42?
It makes the random split reproducible when the dataset and row order remain the same. Reproducibility makes it easier to compare models under the same evaluation conditions.
MODEL 01 · BASELINE

Linear Regression

Linear Regression estimates a continuous target by learning a linear relationship between the input features and the target price.

+
Advantages

Simple, fast and comparatively easy to interpret.

!
Consideration

Complex non-linear relationships may not be represented well by a linear model.

MODEL 02 · SELECTED

Decision Tree Regressor

A Decision Tree Regressor learns decision rules from the feature values and predicts a numerical output from the resulting tree structure.

+
Advantages

Can represent non-linear relationships and feature interactions.

!
Consideration

Tree depth and leaf-size settings affect generalization.

Decision Tree Configuration

The recorded model configuration used a maximum depth of 20, a minimum of 5 samples per leaf, and random state 42. These settings control tree complexity and make the training procedure reproducible.

from sklearn.tree import DecisionTreeRegressor from sklearn.linear_model import LinearRegression from sklearn.pipeline import Pipeline # Example model definitions from the project workflow linear_model = Pipeline(steps=[ ("preprocessor", preprocessor), ("model", LinearRegression()) ]) decision_tree_model = Pipeline(steps=[ ("preprocessor", preprocessor), ("model", DecisionTreeRegressor( max_depth=20, min_samples_leaf=5, random_state=42 )) ]) linear_model.fit(X_train, y_train) decision_tree_model.fit(X_train, y_train)

This is an explanatory representation of the training approach. The saved model pipelines remain the source of truth for the application's actual predictions.

Why not Logistic Regression?
Logistic Regression is designed mainly for classification tasks, where the output is a class or class probability. HomeMate predicts a continuous property price, so Linear Regression and Decision Tree Regressor are more appropriate algorithms for the comparison.

Limitations and Future Improvements

Understanding what the current model can and cannot do.

Current Limitations

!
Historical listing data

Predictions reflect patterns in the dataset and may not match current market prices.

!
Limited input variables

Factors such as exact locality, age of building, amenities and market conditions may not be represented.

!
Prediction uncertainty

A model estimate is not a guaranteed sale price or a professional property valuation.

Future Improvements

+
More features

Add verified locality, amenities, building age and other useful attributes.

+
Further model experiments

Test other regression algorithms and tune hyperparameters.

+
Stronger validation

Use cross-validation and compare errors across price ranges and cities.
